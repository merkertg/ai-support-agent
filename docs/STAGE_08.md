# Этап 08. Интерфейс оператора Streamlit

Цель — выполнять обычную работу поддержки через браузер: открыть обращение,
посмотреть клиента и продукт, изучить результат агента, проверить источники
и принять решение по черновику. Интерфейс обращается к существующему HTTP API.
SQL-запросы, вызовы модели, сохранение решений и продолжение LangGraph остаются
на стороне FastAPI.

Предыдущий этап: [процесс согласования](STAGE_07.md). Для первого показа
удобнее [подготовить демонстрацию](DEMO.md). Автоматические оценки описаны
в [этапе 09](STAGE_09.md), упаковка — в [этапе 10](STAGE_10.md).

## 1. Что есть в интерфейсе

| Раздел | Для чего нужен |
| --- | --- |
| **Обзор** | Полные агрегаты API: обращения, открытые и приоритетные, проанализированные обращения, время анализа, решения по предложениям. |
| **Обращения** | Фильтры клиента, продукта и статуса; создание обращения; карточка; ручная смена статуса; история запусков и сообщений. |
| **Очередь проверки** | Предложения `pending`, `approved`, `rejected`; фильтр обращения; редактирование ответа при одобрении и причина отклонения. |
| **База знаний** | Поиск по запросу и коду продукта; найденные фрагменты, ключи и пути источников. |
| **Справочники** | Просмотр и создание клиентов, продуктов, лицензий и сотрудников. |

Списки загружаются страницами по 20 записей. Кнопки «Назад» и «Далее»
переключают страницу; смена фильтра возвращает первую страницу. Пустая страница
означает отсутствие подходящих записей, а ошибка API показывается отдельно.

Сотрудник входит своим токеном: поле **Токен сотрудника** в боковой панели
(ввод скрыт). Без токена страница не обращается к API. После входа видно имя
и роль; автором решения API записывает владельца токена. Форма решения есть
только у ролей `reviewer` и `admin`, создание сотрудников с выбором роли —
только у `admin`. На этапе 08 здесь было поле «ID сотрудника» без проверки
полномочий; токены и роли добавлены позже ([этап 10, раздел 9](STAGE_10.md#9-аутентификация-роли-и-лимит-изменений)).
Стенд рассчитан на локальную демонстрацию с вымышленными данными.

## 2. Как соединены компоненты

```text
Браузер оператора
    │ открывает страницу Streamlit
    ▼
operator_ui/main.py → operator_ui/app.py
    │ формы и отображение; сетевой клиент operator_ui/client.py
    │ HTTP GET / POST / PATCH
    ▼
FastAPI
    ├── PostgreSQL: обращения, сообщения, предложения, checkpoint LangGraph
    ├── Qdrant: фрагменты базы знаний
    └── mock или явно настроенный OpenAI
```

У процесса UI нет необходимости в `DATABASE_URL` и ключе OpenAI. Ему достаточно
адреса API в `API_URL`. В браузере нет формы произвольного адреса API:
настройку задаёт запускающий приложение администратор.

Секретный ключ модели вводится только в серверную конфигурацию FastAPI.
Поле ключа лицензии в форме анализа скрывает ввод; при отображении лицензий
интерфейс маскирует ключи. Токен сотрудника хранится только в сеансе
браузера и не попадает в сообщения об ошибках. Эти меры относятся к интерфейсу;
права проверяет API, а конфигурацию сервера защищает администратор.

## 3. Запуск через Docker Compose

В корне проекта подготовь `.env`, если его ещё нет. Существующий файл не
заменяй: он может содержать настройки уже созданного стенда.

```bash
if [ ! -f .env ]; then
  cp .env.example .env
fi
docker compose up --build --detach --wait --wait-timeout 180 ui
docker compose exec -T api python -m app.knowledge.ingest
docker compose ps --all
```

В PowerShell на Windows ([аналоги команд](instructions/windows.md)):

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose up --build --detach --wait --wait-timeout 180 ui
docker compose exec -T api python -m app.knowledge.ingest
docker compose ps --all
```

На уже работающем стенде та же команда пересобирает образы и пересоздаёт
только изменившиеся контейнеры. Тома PostgreSQL и Qdrant сохраняются вместе
с записями, ожидающими решениями и индексом. `down --volumes` не нужен.

Открой [интерфейс оператора](http://127.0.0.1:8502).
FastAPI и Swagger доступны по адресу [документации API](http://127.0.0.1:8001/docs).
Compose запускает PostgreSQL, миграции, Qdrant и API перед UI. Индексация
второй командой нужна перед демонстрацией поиска и анализа; она переиспользует
неизменённые статьи и не требует повторной загрузки каждого фрагмента.

Для бесплатного учебного режима оставь в `.env`:

```text
LLM_PROVIDER=mock
EMBEDDING_PROVIDER=mock
```

Это два отдельных провайдера: mock-модель сама по себе не отключает платные
эмбеддинги, если `EMBEDDING_PROVIDER` вручную переключён на `openai`.
Живые OpenAI-запросы в текущий учебный проход не входят.

## 4. Запуск UI в Python на компьютере

API может продолжать работать в Docker. Для UI установи отдельную группу
зависимостей `ui` из того же `uv.lock`:

```bash
uv sync --locked --group ui
API_URL=http://127.0.0.1:8001 uv run --locked --group ui streamlit run \
  operator_ui/main.py --server.address 127.0.0.1 --server.port 8501
```

В PowerShell на Windows ([аналоги команд](instructions/windows.md)):

```powershell
uv sync --locked --group ui
$env:API_URL = 'http://127.0.0.1:8001'
uv run --locked --group ui streamlit run `
  operator_ui/main.py --server.address 127.0.0.1 --server.port 8501
Remove-Item Env:API_URL
```

Открой [UI, запущенный в Python](http://127.0.0.1:8501).
Внутри Docker UI обращается к `http://api:8000`; на компьютере нужен
опубликованный адрес `http://127.0.0.1:8001`. `localhost` внутри контейнера
означает сам этот контейнер.

| Настройка | Значение и смысл |
| --- | --- |
| `API_URL` | Корневой HTTP(S) URL FastAPI. Без credentials, пути, query и fragment. |
| `UI_PORT` | Порт Compose для браузера; по умолчанию `8502`. |
| `--server.port` | Порт самостоятельного процесса Streamlit; в примере `8501`. |
| Группа `ui` | Streamlit и его HTTP-клиент; устанавливается отдельно от минимального API. |

## 5. Первый учебный проход

### 5.1. Подготовить данные

```bash
uv run --locked python scripts/demo_scenario.py --url http://127.0.0.1:8001
```

В PowerShell на Windows ([аналоги команд](instructions/windows.md)):

```powershell
uv run --locked python scripts/demo_scenario.py --url http://127.0.0.1:8001
```

Скрипт проверит оба mock-провайдера и готовность индекса до первого POST.
Он выведет JSON с `customer_id`, `product_id`, `operator_id`, `license_id`,
`ticket_id`, `run_id`, `suggestion_id`. Эти значения зависят от содержимого БД.
В основном сценарии предложение остаётся `pending`, сообщения клиенту нет.

Повтор команды переиспользует учебные записи. Если ты уже рассмотрел
предложение через UI, повтор покажет его текущее решение и не создаст второй
тикет или новый анализ. Подробные правила — в [этапе 10](STAGE_10.md).

### 5.2. Открыть обращение

1. В боковой панели укажи `operator_id` из JSON.
2. Выбери **Обращения**.
3. В поле **Открыть обращение по ID** введи `ticket_id`.
4. Изучи описание и раздел **Клиент, продукт и лицензии**.
5. В истории открой `run_id`. Уже сохранённый запуск читается через GET:
   модель повторно не вызывается.
6. Проверь итог, черновик, ключи источников и раскрывающуюся трассу инструментов.

Для этого тикета демонстрационный скрипт уже выполнил анализ. Кнопка
**Запустить анализ** создаёт новый запуск только по явной отправке формы;
обычное обновление страницы не запускает анализ повторно.

### 5.3. Принять решение

1. Перейди в **Очередь проверки** → **Ожидают проверки**.
2. При необходимости отфильтруй список по `ticket_id`.
3. В поле **Открыть предложение по ID** введи `suggestion_id`.
4. Прочитай черновик и выбери **Одобрить** или **Отклонить**.
5. Для одобрения проверь и при необходимости исправь итоговый текст.
   Для отклонения укажи причину.
6. Отметь **Я проверил текст и подтверждаю решение**, затем нажми
   **Сохранить решение**.

Одобрение создаёт ровно одно учебное сообщение оператора в БД и переводит
обращение в `waiting_customer`. Внешнее письмо не отправляется.
Отклонение сохраняет причину и оставляет обращение без нового сообщения.
Повторное решение API отклоняет с `409`; UI предлагает обновить данные.
Для обращения `resolved` или `closed` одобрение недоступно: такое предложение
можно только отклонить, а кнопка анализа в карточке выключена.

### 5.4. Проверить результат

Вернись в **Обращения** и открой тот же `ticket_id`. После одобрения в разделе
сообщений появится утверждённый текст. В очереди выбери **Одобрены** или
**Отклонены**, чтобы увидеть автора, время и комментарий решения.

Ручная смена статуса находится в отдельной форме карточки. Изменение статуса
само по себе не запускает агента и не одобряет предложения.

## 6. Найти статью

Открой **База знаний** и отправь форму:

- Запрос: `Сервер не запускается после обновления`.
- Код продукта: `techflow-server`.
- Число фрагментов: например, `3`.

Раскрой найденный фрагмент: интерфейс показывает ключ статьи, заголовок,
раздел, сходство, текст и путь исходного Markdown. Поиск с кодом продукта
разрешает статьи этого продукта и общие статьи. Общая кнопка обновления
страницы не повторяет поиск: результат сохраняется в состоянии текущей сессии.

## 7. Что означают числа на обзоре

Обзор получает агрегаты `GET /api/dashboard` из БД. Это статистика всего
стенда, а не подсчёт первых 20 строк списка.

- Открытые обращения: только `status=open`.
- Высокий приоритет: `high` и `critical` среди незакрытых обращений.
- Проанализированные: обращения с завершённым запуском.
- Среднее время анализа: длительность завершённых запусков.
- Доля одобрений: `approved / (approved + rejected)`; `pending` не участвуют.

Если завершённых запусков или решений ещё нет, UI показывает **Нет данных**
для соответствующего среднего или доли. Ноль и отсутствие данных имеют
разный смысл.

## 8. Ошибки и повторные действия

| Что видно | Что проверить |
| --- | --- |
| `dependency failed to start`, нет `docker.sock` | Docker Desktop остановился во время запуска. Запусти его, дождись ответа `docker version` и повтори ту же команду `up`; тома не удаляются. |
| Нет соединения с API | Состояние `docker compose ps`; `API_URL`; адрес контейнера и опубликованный порт. |
| `404` | Существует ли введённый ID; взят ли он из текущей БД. |
| `409` | Уникальная запись уже создана; предложение уже рассмотрено; обращение закрыто (его предложение можно только отклонить, анализ недоступен); у обращения уже есть предложение на проверке или идёт анализ. Обнови карточку и очередь перед повтором. |
| `422` | Обязательные поля, положительные ID, длину текста, связи лицензии и временные границы. |
| `503` | Миграции, PostgreSQL, статус Qdrant и настройку провайдера. |
| Тайм-аут анализа | Сначала прочитай историю запусков: запрос мог успеть сохраниться. |
| «Код запроса для администратора» | Найди строку журнала: `docker compose logs api` и поиск этого кода. В журнале класс ошибки, код SQLSTATE или ответ провайдера, но не тексты запросов. |
| Источники не найдены | Индексацию, код продукта и слова запроса; mock-поиск использует общие слова, а не полноценное понимание синонимов. |

HTTP-клиент не повторяет POST и PATCH автоматически. При потере ответа запись
могла сохраниться на сервере: сначала открой карточку, историю или очередь.
Неожиданные тела ошибок, SQL и traceback не выводятся как текст оператора.
При ошибке API интерфейс показывает код запроса из заголовка `X-Request-ID`:
по нему администратор находит подробности в JSON-журнале API.

## 9. Как проверяется UI

Тесты HTTP-клиента проверяют методы, пути, пагинацию и обработку ошибок.
Streamlit `AppTest` проверяет отображение и действия формы с подменённым API:
так можно убедиться, что обычный rerun не создаёт записи, а отправка формы
делает один ожидаемый запрос.

```bash
uv run --locked --group ui pytest tests/test_operator_ui.py -q
```

В PowerShell на Windows ([аналоги команд](instructions/windows.md)):

```powershell
uv run --locked --group ui pytest tests/test_operator_ui.py -q
```

Имена и состав всех проверок смотри в [инструкции тестирования](instructions/testing.md),
а фактически выполненные проверки — в [отчёте верификации](VERIFICATION.md).
AppTest проверяет поведение виджетов; просмотр настоящего браузера отдельно
нужен для оценки расположения и читаемости интерфейса.

Официальный справочник:
[Streamlit AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).
