## Приоритет 1 — завершить безопасное восстановление

1. [Создание копии](../scripts/backup.py) сравнивает ревизию и количества
   строк/точек. Изменение содержимого без изменения количества не выявляется.
   Обещание в [инструкции](instructions/backup.md), что любое изменение данных
   отклоняет копию, нужно уточнить. Для согласованной пары хранилищ следует
   требовать остановку процессов записи либо обеспечивать явную координацию.
2. При restore Qdrant заменяется раньше PostgreSQL. Ошибка между шагами
   может оставить разные версии двух хранилищ. Замена PostgreSQL сначала
   удаляет прежнюю БД, затем переименовывает временную. Нужны сохранение
   старой пары до успешного переключения и проверяемая процедура возврата.
3. Добавить тесты принудительного сбоя между заменами и подтвердить новый
   CI после завершения кода. Проверка счастливого пути этого не доказывает.

Готовность: успешное восстановление на чистом стенде; отказ в каждом шаге
не уничтожает возможность возврата к прежним данным; ограничения инструкции
совпадают с поведением. Расписание, ротация и внешнее шифрованное хранилище —
следующая отдельная работа.
