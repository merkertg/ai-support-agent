# Этап 01. Подробное руководство по первому API

Этот документ объясняет текущий код проекта и помогает запустить его на твоём Mac.
Все команды ниже выполняются в Terminal, из папки `ai-support-agent`.

## 1. Что уже создано

Сейчас приложение умеет принимать один служебный запрос: `GET /health`.
Оно возвращает статус `ok` и имя сервиса `ai-support-agent`.
FastAPI также предоставляет описание API и интерактивную документацию.
Автоматический тест проверяет код и содержимое ответа `/health`.

Это фундамент будущей системы технической поддержки.
Клиентов, лицензий, обращений, PostgreSQL, RAG и AI-агента в коде пока нет.
Следующий этап добавит PostgreSQL, модели данных и миграции.

На первом этапе нужно понять цепочку:

```text
Браузер → HTTP-запрос → Uvicorn → FastAPI → функция health → HTTP-ответ
```

## 5. Что означают HTTP, GET, endpoint и JSON

**HTTP** — правила обмена запросами и ответами между клиентом и сервером.
У запроса есть метод и адрес; у ответа — код состояния, заголовки и содержимое.
Браузер в нашем примере — клиент, запущенное приложение — серверная сторона.

**GET** означает запрос на получение представления ресурса.
Открывая `/health` в адресной строке браузера, ты отправляешь GET-запрос.

**Endpoint** — конкретная операция API, определяемая методом и путём.
В нашем приложении это `GET /health`.
Другой метод по тому же пути может означать другую операцию.
Например, `POST` часто используют для создания ресурса или передачи данных.
POST-обработчик `/health` у нас не создан.

**API** — интерфейс взаимодействия программ.
Позднее интерфейс оператора сможет обращаться к API так же, как сейчас браузер.

**200 OK** — код успешного HTTP-ответа.
Он помогает клиенту понять результат без анализа текста сообщения.

**JSON** — текстовый формат обмена данными.
В нашем ответе есть объект с двумя строковыми ключами и строковыми значениями.
Внутри Python функция создаёт словарь, а в HTTP-ответе клиент получает JSON.
Словарь Python и JSON-текст похожи внешне, но это разные представления данных.

## 6. Разбираем app/main.py

В файле есть русские комментарии и docstring: они объясняют код и не отключают его.
Ниже разобраны выполняемые части файла.

### Импорт

```python
from fastapi import FastAPI
```

`fastapi` — установленная библиотека, `FastAPI` — класс из этой библиотеки.
Импорт делает имя `FastAPI` доступным в нашем модуле.
Если библиотека не установлена в выбранном окружении, импорт завершится ошибкой.

### Создание приложения

```python
app = FastAPI(
    title="AI Support Agent",
    description="AI-powered technical support system",
    version="0.1.0",
)
```

`FastAPI(...)` создаёт один объект приложения. Переменная `app` хранит этот объект.
Позднее Uvicorn найдёт его и начнёт передавать ему HTTP-запросы.

Аргументы задают метаданные:

- `title` — название в документации.
- `description` — описание назначения проекта.
- `version` — версия нашего API; это не версия Python или библиотеки FastAPI.

Описание отражает цель будущего продукта. Текущие возможности ограничены этапом 01.
Создание объекта не запускает сетевой сервер: его запускает отдельная команда Uvicorn.

### Регистрация маршрута

```python
@app.get("/health", tags=["Health"])
```

Строка с `@` — декоратор. Здесь он регистрирует функцию, написанную сразу ниже,
как обработчик GET-запросов по пути `/health`.

`tags=["Health"]` группирует маршрут в разделе `Health` на странице `/docs`.
Это оформление документации; сам адрес endpoint остаётся `/health`.

### Объявление функции

```python
async def health() -> dict[str, str]:
```

`def` объявляет функцию, `health` — её имя, пустые скобки означают отсутствие аргументов.
FastAPI вызывает обработчик, когда получает соответствующий запрос.
В коде другого Python-модуля имя `health` само по себе не является HTTP-адресом.
Связь с `/health` создаёт декоратор.

`async def` объявляет асинхронную функцию.
Она может ожидать асинхронные операции через `await`, например обращение к API.
Сейчас таких операций нет: функция сразу создаёт небольшой словарь.
Использовать `async def` без `await` в таком обработчике допустимо.
Само слово `async` не делает вычисления быстрее.

`-> dict[str, str]` — аннотация возвращаемого типа:

- `dict` — словарь;
- первый `str` — тип его ключей;
- второй `str` — тип его значений.

В самом Python аннотация служит описанием ожидаемого типа и не проверяет значения автоматически.
Однако FastAPI использует аннотацию результата для схемы, проверки и сериализации HTTP-ответа.
Поэтому поведение этого API включает обработку аннотации со стороны фреймворка.
Поле `status` со значением `"ok"` при этом проверяется нашим тестом:
тип `str` сам по себе не требует именно такого текста.

### Возврат ответа

```python
return {
    "status": "ok",
    "service": "ai-support-agent",
}
```

`return` завершает функцию и возвращает словарь вызывающей стороне.
FastAPI обрабатывает результат и формирует JSON-ответ.
Так как другой код ответа не задан, для успешного выполнения используется `200`.

`status` сообщает, что обработчик дошёл до формирования ответа.
`service` помогает понять, какое приложение ответило.
Эта функция не проверяет базу данных, интернет или работоспособность будущего AI-агента.

### Комментарий и docstring

Комментарий начинается с `#`. Python не выполняет его как инструкцию.
Закомментировать выполняемую строку — значит поставить перед ней `#` и отключить её.
В нашем коде комментарии добавлены рядом с рабочими строками, поэтому приложение продолжает работать.

Docstring — строка в тройных кавычках в начале модуля или функции.
Она описывает назначение кода и доступна инструментам документации.
FastAPI может использовать docstring обработчика в описании операции.
Docstring не заменяет тело функции: после него выполняется обычный код с `return`.

## 7. FastAPI, Uvicorn и ASGI: кто за что отвечает

**FastAPI** определяет поведение приложения: маршруты, обработчики и формирование ответов.

**Uvicorn** принимает сетевые подключения и передаёт события приложению.
Он слушает адрес и порт, указанные в команде запуска.

**ASGI** — стандартный интерфейс между Python-приложением и сервером,
поддерживающий асинхронную работу. Через него взаимодействуют FastAPI и Uvicorn.
Для первого этапа писать собственный ASGI-код не требуется.

Разбор команды запуска:

| Часть | Значение |
| --- | --- |
| `.venv/bin/python` | Python из окружения проекта |
| `-m uvicorn` | Запустить установленный модуль Uvicorn этим Python |
| `app.main:app` | Импортировать модуль `app.main` и взять из него объект `app` |
| `--reload` | Перезапускать приложение после изменений кода при разработке |
| `--host 127.0.0.1` | Слушать локальный адрес этого компьютера |
| `--port 8000` | Использовать TCP-порт 8000 |

В `app.main:app` первая часть `app` — папка-пакет, `main` — файл `main.py` без расширения.
Последняя часть после двоеточия — переменная `app` внутри этого файла.

**uv и Uvicorn — разные программы.**
`uv` управляет Python-окружением и зависимостями; Uvicorn запускает ASGI-приложение.
Команда `uv run uvicorn ...` сначала выбирает окружение, затем запускает в нём Uvicorn.
Прямой вызов `.venv/bin/python -m uvicorn ...` использует уже подготовленное окружение.

## 8. Разбираем tests/test_health.py

Тест нужен, чтобы автоматически заметить изменение ожидаемого поведения API.
Он проверяет тот же объект приложения, который используется при обычном запуске.

```python
from fastapi.testclient import TestClient
from app.main import app
```

Первый импорт берёт тестовый клиент FastAPI. Он опирается на Starlette и HTTPX.
Второй импорт получает объект `app` из нашего `app/main.py`.
Здесь Python загружает модуль и создаёт приложение, но не запускает Uvicorn.

```python
def test_health() -> None:
```

Pytest ищет тестовые файлы, в том числе с именами `test_*.py`, и функции `test_*` внутри них.
В проекте поиск направлен в папку `tests` через `pyproject.toml`.
Поэтому имя файла `test_health.py` и функции `test_health` соответствует правилам поиска.

`-> None` означает, что тест не возвращает полезного результата.
Успех определяется выполнением проверок, а не значением `return`.
Тест написан обычной функцией `def`: TestClient предоставляет синхронный интерфейс.

```python
with TestClient(app) as client:
    response = client.get("/health")
```

`with` открывает контекст тестового клиента и гарантирует его закрытие при выходе из блока.
Внутри блока переменная `client` содержит готовый клиент.
`client.get("/health")` отправляет GET-запрос приложению, а `response` сохраняет ответ.

Запрос проходит внутри тестового процесса, без сетевого порта и отдельного Uvicorn.
Поэтому тест можно запускать при остановленном сервере.
После выхода из `with` клиент закрыт, но сохранённый объект `response` остаётся доступен.

```python
assert response.status_code == 200
```

`status_code` содержит HTTP-код ответа.
`assert` проверяет условие: если оно ложно, возникает ошибка, и Pytest отмечает тест как упавший.

```python
assert response.json() == {
    "status": "ok",
    "service": "ai-support-agent",
}
```

`response.json()` разбирает JSON-текст ответа и возвращает Python-объект, здесь словарь.
Проверяется весь словарь: отсутствующее, дополнительное или изменённое поле приведёт к провалу.
Порядок ключей словаря при таком сравнении не важен.

## 9. Как запустить тест и проверить код

Открой второй Terminal и перейди в проект:

```bash
cd "/Users/arslanbakiev/Desktop/ИИ кузница/ai-support-agent"
.venv/bin/python -m pytest
```

В известном проверенном запуске итог содержит `1 passed, 1 warning`.
`1 passed` означает, что один тест прошёл.
`1 warning` относится к предупреждению совместимости зависимостей Starlette и HTTPX.
Предупреждение сообщает о поведении библиотеки и не означает провал теста.
Его не нужно скрывать или менять зависимости только ради исчезновения строки.
В другом окружении точный текст и наличие предупреждения могут отличаться.

Если увидишь `FAILED` или `ERROR`, прочитай сообщение ниже: это уже не успешный результат.
Обычно Pytest показывает файл, строку и значения, которые не совпали.

Проверь код линтером:

```bash
.venv/bin/ruff check .
```

При отсутствии замечаний ожидается сообщение `All checks passed!`.
Линтер проверяет правила кода, а не работоспособность HTTP-запроса.

Проверь форматирование:

```bash
.venv/bin/ruff format --check .
```

Успешная проверка сообщает, что Python-файлы уже отформатированы.
Число файлов зависит от состава проекта.
Флаг `--check` ничего не переписывает: если формат отличается, команда сообщает об этом.

## 10. Настройки в pyproject.toml

Файл использует формат TOML: секции в квадратных скобках и значения вида `ключ = значение`.
В нём находятся все следующие настройки текущего проекта.

| Настройка | Значение и смысл |
| --- | --- |
| `[project] name` | `ai-support-agent`: имя проекта |
| `version` | `0.1.0`: текущая версия проекта |
| `description` | Описание назначения и первого этапа |
| `readme` | `README.md`: файл основного описания |
| `requires-python` | `>=3.12`: допустим Python 3.12 или новее |
| `dependencies` | `fastapi` и `uvicorn[standard]`: зависимости для работы приложения |
| `[dependency-groups] dev` | `httpx`, `pytest`, `ruff`: инструменты разработки и проверки |
| `[tool.pytest.ini_options] testpaths` | `["tests"]`: искать тесты в папке `tests` |
| `pythonpath` | `["."]`: добавить корень проекта в пути импорта при запуске тестов |
| `[tool.ruff] target-version` | `py312`: учитывать синтаксис Python 3.12 |
| `line-length` | `88`: ориентир длины строки для форматирования |
| `[tool.ruff.lint] select` | `["E", "F", "I", "UP"]`: включённые группы правил |

`uvicorn[standard]` означает Uvicorn с набором дополнительных зависимостей,
в том числе для удобного отслеживания изменений при разработке.

Группы Ruff: `E` — правила оформления из pycodestyle, `F` — проверки Pyflakes,
`I` — порядок импортов, `UP` — рекомендации по современному синтаксису Python.
Настройка `target-version` не устанавливает Python, а сообщает Ruff целевую версию.

В `pyproject.toml` перечислены нужные библиотеки; в `uv.lock` зафиксированы выбранные версии
и зависимости этих библиотек. Это разные задачи двух файлов.

## 11. Как воспроизвести окружение через uv

Этот раздел пригодится на другом компьютере или при пересоздании `.venv`.
Для уже работающего окружения достаточно прямых команд из разделов 3 и 9.
Абсолютный путь в командах `cd` относится к этому Mac; на другом компьютере
подставь путь к своей копии проекта.

1. Установи `uv` по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).
2. После установки открой новый Terminal, чтобы он увидел обновлённый `PATH`.
3. Перейди в корень проекта и выполни команды ниже.

```bash
cd "/Users/arslanbakiev/Desktop/ИИ кузница/ai-support-agent"
uv --version
uv sync --locked
```

Первая команда `uv` должна вывести установленную версию программы.
`uv sync --locked` создаёт или синхронизирует `.venv`, включая группу `dev` по умолчанию.
Для загрузки отсутствующих пакетов и, при необходимости, Python нужен доступ к сети.

`.python-version` содержит `3.12`: uv ориентируется на эту версию при выборе Python.
Это выбор ветки `3.12`, а не закрепление конкретного исправления вроде `3.12.14`.
Требование `>=3.12` в `pyproject.toml` задаёт допустимый диапазон для проекта.

`--locked` требует согласованности `pyproject.toml` и `uv.lock`.
Если изменения зависимостей требуют обновления lockfile, команда завершится с ошибкой,
а не обновит его незаметно. Не редактируй `uv.lock` вручную для исправления такой ошибки.

После синхронизации доступны команды:

```bash
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Проверки выполняй в другом терминале из корня проекта:

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

Они решают те же задачи, что и прямые команды из `.venv`.
Активация окружения через `source` для обоих показанных способов не требуется.

## 12. Что исключено из Git

`.gitignore` исключает `.venv/`, `__pycache__/`, кеши Pytest, Ruff и Mypy,
скомпилированные Python-файлы, результаты сборки, отчёты покрытия и локальные логи.
Также исключены настройки редакторов и `.DS_Store` от macOS.

Правила для `.env` и `.env.*` помогают не добавлять локальные секреты.
Исключение `!.env.example` позволяет хранить шаблон настроек, если он появится позже.
Сейчас для запуска не требуется создавать `.env` или получать API-ключ.

`uv.lock`, `.python-version`, `pyproject.toml`, исходники, тесты и документацию
нужно хранить вместе с проектом. Окружение восстанавливается по этим файлам.
`.gitignore` не удаляет уже отслеживаемые файлы и не заменяет проверку перед коммитом.

## 13. Типичные ошибки

| Симптом | Что проверить и сделать |
| --- | --- |
| `command not found: uv` | Используй готовую `.venv`; для восстановления установи uv по официальной инструкции |
| `python3 --version` показывает `3.9.6` | Запускай `.venv/bin/python`; системный Python для этого проекта не подходит |
| `no such file or directory: .venv/bin/python` | Проверь `pwd`; если `.venv` действительно отсутствует, восстанови её через uv |
| `ModuleNotFoundError: No module named 'app'` | Выполни `cd` в корень проекта; для запуска используется `app.main:app` |
| `No module named fastapi`, `uvicorn` или `pytest` | Проверь выбранный Python; при неполном окружении выполни `uv sync --locked` |
| `Address already in use` | Порт занят; используй другой порт, как показано ниже |
| Браузер не подключается | Проверь, что Uvicorn ещё работает и в адресе указан правильный порт |
| `404 Not Found` на `/` | Корневой маршрут не создан; открой `/health` или `/docs` |
| `404` на другом пути | Проверь написание адреса: нужен `/health` без опечаток |
| `405 Method Not Allowed` | Для `/health` используй метод GET |
| `/docs` пустой, но `/health` работает | Swagger UI загружает ресурсы с CDN; проверь сеть и доступность ресурсов в браузере |

Если порт 8000 занят, сначала открой `/health`: возможно, сервер уже запущен.
Для просмотра ответа можно использовать его. Для собственного запуска с `--reload`
выбери порт 8001, не завершая чужие процессы:

```bash
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

Теперь адреса начинаются с `http://127.0.0.1:8001`, например
[http://127.0.0.1:8001/health](http://127.0.0.1:8001/health).
Старые вкладки с портом 8000 не переключатся автоматически.

Если Swagger UI не загрузился из-за CDN, отдельно открой `/health` и `/openapi.json`.
Доступность JSON и загрузка интерфейса документации — разные проверки.
Сам по себе ответ `200` от `/docs` ещё не доказывает, что браузер загрузил все ресурсы страницы.

## 14. Небольшое упражнение: новое поле ответа

Сначала добейся успешного запуска и прохождения текущего теста.
Затем можно проверить, как изменение API связано с тестами.

1. В словарь, возвращаемый `health`, добавь строку `"info": "First API endpoint",`.
2. Сохрани `app/main.py`; сервер с `--reload` должен перезапустить приложение.
3. Обнови `/health` в браузере: в ответе появится третье поле.
4. Запусти тест без изменения ожидаемого словаря: он должен упасть.
5. Добавь такое же поле в ожидаемый словарь в `test_health.py` и снова запусти тест.

Новый словарь в обоих местах будет таким:

```python
{
    "status": "ok",
    "service": "ai-support-agent",
    "info": "First API endpoint",
}
```

Почему тест сначала падает: сейчас он сравнивает весь ответ, а не только поле `status`.
Изменение контракта API требует обновления и реализации, и ожидаемого результата.
Это учебное изменение не внесено автоматически: выполняй его самостоятельно, когда будешь готов.

Для завершения этапа проверь три результата: сервер запускается, `/docs` открывается,
автоматический тест `/health` проходит. После упражнения также проверь Ruff командами из раздела 9.

Официальные материалы: [первые шаги с FastAPI](https://fastapi.tiangolo.com/tutorial/first-steps/),
[тестирование FastAPI](https://fastapi.tiangolo.com/tutorial/testing/),
[установка uv](https://docs.astral.sh/uv/getting-started/installation/).
